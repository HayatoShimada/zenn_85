前回、Markdown メモ帳（SilverBullet）を MCP サーバー経由で AI エージェントに読み書きさせる話を書きました。今回はその**検索の中身**を作り直した話です。

結論から言うと、検索の単位を「ページ」から「`##` 見出しごとの節」に変え、全文検索とローカル埋め込みをハイブリッドにして、結果に**行番号**を付けました。これでエージェントは「どのページの何行目を読めばいいか」を検索結果だけで判断でき、編集ツールへの受け渡しも行番号ひとつで済みます。

## 前提

- メモは 2 スペース、合計 74 ページ・約 10 万字。PARA × GTD で `Projects/ Areas/ Goals/ Archive/ Journal/` に分かれ、frontmatter に `tags / area / status / due` が付いている
- サーバーは Raspberry Pi 5（8GB、GPU なし）。MCP サーバーは Node.js
- 片方のスペースは本業のメモで、**本文をインターネットに出さない**のが運用上の前提

この規模だと「巨大な RAG」は要りません。むしろ**小さく正確に**引けることが大事で、設計はそこに寄せています。

## 何が問題だったか

作り直す前の `search_notes` は、小文字化した部分一致（`includes()`）だけでした。

- ランキングがない（更新順に並ぶだけ）
- ページ単位でしか返せないので、エージェントは結局ページ全文を読み直す
- 言い換えが拾えない（「セール」で「キャンペーン」は出ない）

エージェントは「探す → 読む → 書く」を繰り返すので、検索が粗いと毎回の読み直しでコンテキストを食います。

## 設計の 3 層

### 1. 書き方の契約（メモ側）

索引がどれだけ良くても、入力が崩れていると効きません。既存の慣習は変えず、次だけ足しました。

- frontmatter に `summary:` を 1 行（Projects / Areas / Goals / Resources）
- `##` 見出し 1 つあたり 1,500 字を目安。超えるなら `###` で割る
- 日報は固定の見出し順（本日の意図 / Inbox 処理 / やったこと / 振り返り）を守る。見出しがそのまま文脈になる
- リンクは `[[path|表示名]]`。ページ名は動かさない

これをスペース内の `Resources/メモの書き方.md` に置いて、テンプレートにも `summary:` を足してあります。

### 2. 索引（節・文脈・リンク）

**節が検索の最小単位**です。各節には、埋め込みと全文検索の両方に使う `context_text` を作ります。

```
[85memo / Projects/スウェットキャンペーン_9月末 tags: project area: オンライン販売 status: active due: 2026-09-30 > Next actions]
* [ ] キャンペーンの内容・期間・告知文を決める #next [due: 2026-09-18]
* [ ] バナーを作り、オンラインとブログに載せる
```

先頭の `[ ... ]` が肝で、スペース・ページ・見出しパス・メタデータを**決定的に**前置しています。Anthropic の contextual retrieval は LLM に文脈を書かせますが、ここでは構造から機械的に作ります。本文が外に出ないし、コストもゼロです。それでいて「Next actions という節が、どのプロジェクトの、どんな状態のものか」が節単体で分かるようになります。

索引には他に、wikilink の順・逆リンク（`related_notes` で辿る）と、タスク行（`* [ ] ...`）を行番号つきで持たせています。

索引は起動時に**メモリ上の SQLite**へ組み直します。74 ファイルで 0.7 秒です。以後はファイルの mtime を見て、変わったページだけ差し替えます。永続化するのは埋め込みだけ（後述）。

SQLite は公式の WASM 版（`@sqlite.org/sqlite-wasm`）を使っています。ネイティブの better-sqlite3 は Pi のプリビルドが手元の環境で安定しなかったので、ネイティブ依存を持たない方を取りました。コーパスが小さいので速度差は問題になりません。

### 3. 検索（ハイブリッド + RRF）

**全文検索**は SQLite FTS5 の `trigram` トークナイザです。形態素解析なしで日本語の部分一致と BM25 が使えます。ただし 2 つ癖があります。

- 3 文字未満の語は引けない（結果が空になる）→ `LIKE '%語%'` で補う
- 「スウェットのキャンペーン」のように助詞でつながった語は 1 語扱いになる → 助詞（の・を・に・は…）で切って語を増やす

**意味検索**は `multilingual-e5-small`（ONNX、int8 量子化）を Pi の CPU で動かします。transformers.js から使えて、モデルのロードが約 1.7 秒、1 節の埋め込みが 20ms 程度。384 次元なので、節の数が数百なら総当たりの内積で十分で、ANN は要りません。ベクトルは節のハッシュをキーに SSD にキャッシュし、変わった節だけ計算し直します。モデルは**意味検索が初めて要求されたときだけ**読むので、全文検索だけの呼び出しは軽いままです。

2 つの結果は Reciprocal Rank Fusion（k=60）で統合し、ページ名の一致・`status: active`・日報の鮮度（半減期 30 日）で少し加点します。同じページからは最大 2 節まで。

返すのはこの形です。

```json
{
  "page": "Projects/スウェットキャンペーン_9月末",
  "heading_path": "Next actions",
  "line_start": 17,
  "line_end": 20,
  "why": ["lexical", "semantic", "title"],
  "snippet": "…キャンペーンの内容・期間・告知文を決める…"
}
```

`why` を返しているのは、エージェントが「語が当たったのか、意味が近いだけなのか」を見て次の手を選べるようにするためです。

## MCP の面

ツールは小さく、合成できる形にしました。

| ツール | 役割 |
|---|---|
| `search_notes` | 節単位の検索。`mode`（hybrid / lexical / semantic）と `tag / area / status / since` のフィルタ |
| `read_section` | `page` と `line_start` で節本文を行番号つきで返す |
| `related_notes` | リンク先・被リンク・意味的に近い節 |
| `recent_changes` | 最近更新されたページ |
| `complete_task` など | 既存の書き込みツール。行番号と mtime を受け取る |

典型的な流れは `search_notes` → `read_section` → `complete_task` で、**行番号だけを受け渡せば済みます**。ページ全文を読む必要がなくなりました。

ページは MCP resources（`memo://<space>/<page>`）としても公開しているので、ホスト側からそのまま添付できます。本業側のスペースの結果には `confidential: true` を付けて、公開物に転載しないようエージェントに伝えています。

## 効果を数字で

「埋め込みを足す価値があるのか」は測っておきたかったので、実際のメモから 24 問（質問 → 期待するページ）のセットを作って比べました。

| mode | recall@1 | recall@5 | MRR |
|---|---|---|---|
| lexical | 0.71 | 0.88 | 0.775 |
| semantic | 0.63 | 0.83 | 0.721 |
| **hybrid** | **0.79** | **0.92** | **0.856** |

単体では全文検索の方が強く、意味検索は少し劣ります。ですが合わせると両方を上回ります。たとえば「メール会員向けの割引」という質問は、ページ側が「20％OFF」と書いているので全文検索では当たりません。意味検索がそれを拾い、全文検索が取りこぼした分を埋める形になっています。

このセットは `npm run eval` で回るようにしてあり、検索を触ったら数字が動くようにしています。

## まとめ

- 検索の単位を**節**にし、**行番号**を返す。エージェントの「読み直し」が消える
- 節の先頭に構造から作った文脈を前置する。LLM に書かせなくても効く
- 日本語は FTS5 trigram で十分引ける。短語と助詞だけ手当てする
- 埋め込みは**ローカル**で。方針（本文を外に出さない）を守ることが設計要件だった
- 評価セットを先に作ると、埋め込みを入れる根拠を数字で持てる

コーパスが小さいときの RAG は、派手な仕組みより「単位・文脈・行番号」の 3 つを揃えるだけでかなり変わります。
